Date: 2026-10-29 (Asia/Bangkok). Scope: consolidated, selective source review of the current single-user RAG MVP. Deliverable: this report only. README reconciliation is proposed for Phase 0D; neither README is edited here.

## 1. Executive Summary

**Provisional verdict: the source supports a Functional MVP, with explicit recovery and verification limitations.** The implemented vertical slices connect document ingestion/versioning, active-version retrieval, history-aware generation, JSON/SSE responses, persisted conversations, and a Next.js workspace. This is an implementation assessment, not a fresh demonstration that these paths operate successfully together. Primary evidence: `backend/app/ingestion.py::IngestionService._process`, `backend/app/rag/pipeline.py::prepare_rag_request`, `backend/app/api/chat.py::chat_stream`, `backend/app/conversation_service.py::ConversationService`, and `frontend/components/chat/chat-preview.tsx::ChatWorkspace`.

The 26 existing findings remain applicable to this checkout: **7 CONFIRMED_DEFECT, 3 CONFIRMED_GAP, 14 DESIGN_RISK, and 2 DOCUMENTATION_MISMATCH**. These are the original classifications, not 26 observed runtime failures. No new finding is introduced. The most consequential existing concerns are bounded reconciliation starvation (F02), ambiguous terminal-persistence/guard-release outcomes (C03), abandoned session guards (C04), and evaluation namespace collision under an accepted boundary configuration (U01). U01 blocks approval of unsafe live evaluation, not ordinary application startup by itself.

Citation identity validation is implemented; factual support is not established by valid IDs. Attachment text/Excel preview is implemented; citation source-content opening and PDF preview are not. Evaluation is a small heuristic baseline and does not certify current HTTP/SSE, persistence, browser behavior, or representative answer quality (`backend/app/citation_mapping.py::map_verified_citations`; `frontend/components/chat/citation-content.tsx::CitationContent`; `backend/scripts/eval_history_cli.py::_acceptance`).

### Core paths and their boundaries

1. **Upload/version → retrieval publication.** Multipart validation → immutable raw save → Mongo document/version/job records → temporary materialization → PDF/text/Markdown/XLSX parser → recursive character splitting → Gemini document embeddings → chunk plan → candidate Qdrant upsert/count → conditional active-pointer publication. Delete unpublishes before vector cleanup; raw/audit data remains. Re-index creates a new version from active raw bytes. Evidence: `backend/app/api/documents.py::{_read_upload,upload_document,update_document,reindex_document,remove_document}`, `backend/app/ingestion.py::{ingest,_process,reconcile_processing}`, `backend/app/document_service.py::{reindex,delete}`, `backend/app/document_repository.py::{complete_and_activate,unpublish}`. Parser and recovery limitations remain F01–F07.
2. **Chat → scoped retrieval → generation.** Shared preparation loads completed whole-turn history, resolves session scope to active version IDs, conditionally rewrites only the retrieval query, retrieves with server-side version filtering, budgets history/chunks/original query, and renders the generation prompt. Empty explicit scope returns no documents without an unfiltered search. Evidence: `backend/app/rag/pipeline.py::{prepare_rag_request,prepare_rag_request_from_components,_resolve_active_version_ids}`, `backend/app/rag/retriever.py::QdrantActiveVersionRetriever._get_relevant_documents`, `backend/app/history.py::ConversationHistoryLoader`, `backend/app/context_budget.py::ContextBudgetBuilder`, `backend/app/query_rewriting.py::QueryRewriter`. Original query may be budget-truncated for generation; it is not replaced by the retrieval rewrite.
3. **Conversation/SSE lifecycle.** A session guard atomically reserves two sequence numbers; message-pair insertion, STREAMING transition, terminal replacement and guard release are separate operations. SSE prepares before acquiring the persistent turn; JSON prepares inside its guarded generation callback. Pre-header errors use HTTP/JSON; after headers, supported generation/persistence failures use an SSE error terminal. The provider loop has a timeout, not a whole-request deadline. Evidence: `backend/app/conversation_repository.py::{begin_generation,create_message_pair,mark_assistant_streaming,finalize_assistant_message,release_generation}`, `backend/app/conversation_service.py::{answer_with_persistence,begin_streaming_turn,finalize_streaming_turn}`, `backend/app/api/chat.py::{chat_stream,_encode_provider_stream_impl,_encode_provider_stream}`. C01–C08 qualify these guarantees.
4. **Frontend send/restore.** `ChatController.submit` prevents an overlapping local submit, creates a session when needed, assigns IDs from SSE start, accumulates deltas, and checks terminal messages against restored history. It preserves live ordered sources when reconciliation succeeds. Stop/unmount aborts local work; no automatic generation replay/resume is implemented. Session components/controllers use aborts and keyed instances to reject obsolete work. Evidence: `frontend/lib/chat/controller.ts::{submit,acceptEvent,stop,dispose}`, `frontend/components/chat/session-chat.tsx::SessionChat`, `frontend/components/chat/chat-preview.tsx::ChatPreview`, `frontend/lib/sessions/history.ts::{loadMessageHistory,HistoryController}`. These controls are not proof of every mounted/network interleaving.
5. **Attachment and preview.** Upload-ready references carry document/version IDs; backend resolves version ownership, nondeleted document and INDEXED attachment status and stores server-derived filename. Attachments do not modify retrieval scope. A historical attachment can refer to an older indexed immutable version while retrieval uses the current active pointer. Preview fetches that referenced version, supports text/Markdown and Excel, and explicitly returns unsupported for PDF. Evidence: `backend/app/attachments.py::{resolve_version,resolve_attachments,preview_version}`, `backend/app/attachment_models.py`, `frontend/hooks/use-chat-attachments.ts::useChatAttachments`, `frontend/components/chat/{message-attachment,document-preview}.tsx`. Resizable preview width, pointer handling and sessionStorage are in `frontend/components/chat/document-preview-sheet.tsx`; actual browser behavior remains NOT_VERIFIED here.
6. **Citations and restoration.** Prompt-selected sources retain order; `[n]` maps to that ordered list with server-owned UUID identities, not model-invented IDs. SSE sends candidate metadata but deliberately emits no realtime citation events. Terminal persistence recomputes citations. History carries citation identities but no ordered source array; UI restores `sources: []` and displays saved identities without inventing ordinals. Citation drawer does not open raw content. Evidence: `backend/app/rag/pipeline.py::prepare_rag_request_from_components`, `backend/app/rag/prompt.py::format_context_blocks`, `backend/app/citation_mapping.py::map_verified_citations`, `backend/app/api/chat.py::_encode_provider_stream_impl`, `backend/app/conversation_schemas.py::MessageResponse`, `frontend/lib/sessions/history.ts::historyMessageToViewMessage`, `frontend/lib/chat/citation-panel.ts::buildCitationPanel`, `frontend/components/chat/citation-content.tsx::CitationContent`.

Evaluation has two seams: `backend/scripts/eval_cli.py::main` uses the alternate `backend/app/rag/chain.py::build_rag_chain`; `backend/scripts/eval_history_cli.py::_run_mode` uses shared internal preparation/generation with supplied history. Neither exercises the complete current HTTP/SSE/persistence/frontend path. Unit/contract/mock/browser tooling is present in `backend/tests/`, `frontend/tests/`, `frontend/e2e/`, `frontend/tests/verify-api-contract.mjs` and `frontend/package.json::scripts`. Existing tests are coverage assets, not current execution evidence.
