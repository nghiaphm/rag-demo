### SSE transport, ordering and safe errors

SSEParser incrementally decodes fatal UTF-8, handles LF/CRLF/CR, comments and multiline data, parses JSON and validates individual events. It intentionally does not enforce transcript ordering. createChatStreamClient adds TranscriptValidator: sequence starts at 1, exactly one start, metadata before content, citation identity membership/deduplication, citation-before-delta, terminal ordering, and EOF completeness ([lib/sse/parser.ts:165–274](frontend/lib/sse/parser.ts#L165), [lib/api/chat.ts:131–233,310–365](frontend/lib/api/chat.ts#L131)). Unknown event is exposed by parser but rejected by chat protocol client; this is intentional separation.

The client distinguishes non-200 HTTP/pre-header failures, unexpected content type/body, malformed/protocol/incomplete stream, consumer callback failure and a valid terminal SSE error. A valid error event is a terminal **result**, not a transport exception. Raw HTTP detail/input/ctx and arbitrary SSE messages are not copied into visible errors by inspected transport/controller paths ([lib/api/client.ts:52–69,122–154](frontend/lib/api/client.ts#L52), [lib/api/chat.ts:84–105,289–307,335–365](frontend/lib/api/chat.ts#L84), [lib/api/error-ux.ts:1–32](frontend/lib/api/error-ux.ts#L1)). REST transport cases TEST_VERIFIED; parser/client Python-dependent suites NOT_EXECUTED.

Intentional JSON/SSE differences remain: partial streamed answers, terminal-vs-HTTP failure timing and absent realtime citation emission; shared preparation does not promise identical generated bytes across separate calls ([api/chat.py:161–163,214–253,397–421,439–516](backend/app/api/chat.py#L161)). C01's backend whitespace transcript discrepancy and C03's release/write split are existing 0B-02 findings, not new U defects. New U04 addresses the separate client-only preterminal abort projection.

Contract verifier coverage: [tests/verify-api-contract.mjs:11–60,62–125,155–174](frontend/tests/verify-api-contract.mjs#L11) exports actual backend OpenAPI plus SSE models without lifespan and with socket blocking, then checks bidirectional TypeScript assignability, keys, nullability/optionality, query/list/multipart and discriminator shape in a virtual compiler file. It is present but NOT_EXECUTED. Its schema-to-type conversion erases numeric/string limits, regex/format distinctions beyond primitive types and semantic validators; it does not prove actual runtime acceptance, endpoint lifecycle or citation interpretation.

### Metric meaning and stored evidence

- `retrieval_metrics`: filename set hit/recall, no rank/precision/chunk identity discrimination; fallback cases return null retrieval metrics. `answer_fact_coverage`: literal boundary-aware expected-substring presence. `faithfulness_ratio`: token overlap, with 1.0 when no content tokens. These are declared heuristics, not entailment/contradiction checks ([evaluation/metrics.py:37–99](backend/evaluation/metrics.py#L37)).
- Fallback scoring only checks inclusion of the refusal phrase; refusal plus contradictory answer can satisfy it. History acceptance checks retrieval/answer coverage, rewrite calls/reason, omitted-history expectation and budget flag, but not citation usability or faithful flag ([eval_cli.py:136–176](backend/scripts/eval_cli.py#L136), [evaluation/history_eval.py:88–136](backend/evaluation/history_eval.py#L88), [eval_history_cli.py:92–132](backend/scripts/eval_history_cli.py#L92)). U03 is a benchmark gate gap; heuristic definitions themselves are not mislabeled as implementation defects.
- Summaries exclude errored runs from quality means but report error counts; all_budgets_ok can be vacuously true if no successful history runs. Read sample size/errors with every rate; a rate is not end-to-end success probability ([eval_cli.py:229–261](backend/scripts/eval_cli.py#L229), [history_eval.py:143–205](backend/evaluation/history_eval.py#L143)). U02 limits latency/token interpretation across retries.

### U01 — Derived evaluation namespace can equal application collection

- **Classification / severity:** CONFIRMED_DEFECT / **High**.
- **Expected invariant:** evaluation mutation must target a collection distinct from application collection for every accepted configuration.

Indexer deletes/upserts scoped eval-document points in that derived collection. [config.py:145–152](backend/app/config.py#L145); [eval_cli.py:51,99–129,294–298](backend/scripts/eval_cli.py#L51); [eval_history_cli.py:30–34,142–150](backend/scripts/eval_history_cli.py#L142).
- **Counterexample:** application collection=`'a' * 250 + '_eval'` is 255 allowed characters. Derived name is identical. A pure Node string/regex check returned length=255, configRegexAccepted=true, applicationEqualsDerivedEvaluation=true. No Python script, provider or database operation was invoked.
- **Impact:** separation guarantee fails; default evaluation may write/delete eval-identified points inside application namespace. - **Recommended action:** before approving any live evaluation, require explicit application/eval-name inequality and collision-safe naming/selection, with boundary-length regression. Do not execute reindex to demonstrate this issue. Related README mismatch recorded in section 9.

### U02 — Retry telemetry drops previous attempt time and usage

- **Classification / severity:** CONFIRMED_DEFECT / **Medium**, conditional retry-accounting path.
- **Expected invariant:** reported case/mode latency and token totals should include retries, or clearly identify successful-attempt-only measurements and expose omitted attempts.
- **Actual implementation / location:** single-turn `_run_case` resets callback/start on each attempt; only final successful attempt contributes returned metrics; all-error result uses null latency/zero tokens. History `_run_mode` similarly overwrites stage latency/prepared metrics and omits previous attempts/backoff; final summary totals successful returned runs. [eval_cli.py:180–218,229–261](backend/scripts/eval_cli.py#L180), [eval_history_cli.py:42–88](backend/scripts/eval_history_cli.py#L42), [history_eval.py:182–225](backend/evaluation/history_eval.py#L182).

- **Recommended action:** retain attempt ledger, end-to-end elapsed time, successful-attempt time, known/unknown usage and retry counts separately; test fake clocks/providers before approving cost/latency claims.
